# 제주 카메라 동물 식별 · 공모전 시연 설계

2026-11-12 설계안. [카메라 PR #5](https://github.com/HighDpsHotCat/Jeju-project/pull/5)의 사진 미리보기를 연결 지점으로 사용한다. 현재 카메라의 촬영·GPS·기기 저장과 별도로, 이 문서는 앞으로 학습하고 평가할 모델의 범위를 정의한다.

## 시연에서 보여줄 동작

1. 발표자가 인쇄물 또는 화면의 동물 한 마리를 휴대폰으로 촬영한다. 모서리나 글자 없이 동물의 주요 특징이 들어오도록 촬영한다. 화면을 다시 찍은 사진은 원본 이미지와 다른 검증 사례로 다룬다.
2. 촬영 직후 미리보기를 띄우면서 자동으로 식별을 시작한다. 저장한 현장 사진에서는 이전 결과를 다시 보여주고, 이전 결과가 없거나 다시 확인하려면 **동물 식별**을 누른다. 사진이 바뀌면 이전 판별 결과를 지운다.
3. 후보가 충분히 구분되면 **조류 · 동박새**처럼 동물군과 국명을 먼저 표시한다. 학명, 후보 상세 보기, **이 종으로 확인**을 제공한다. 두 종이 비슷하면 후보를 최대 세 개 보여주고 **미확인으로 두기**를 제공한다. 사진이 흐리거나 대상이 작으면 가까이 확대해 다시 촬영할 수 있다.
4. 빈 풍경, 대상 밖 종, 특징을 가린 사진은 미확인으로 처리한다. 사진·GPS는 모델 성공 여부와 무관하게 저장한다. 화면이나 인쇄물을 다시 찍은 **시연 기록**은 개인의 야생 관찰 수집률에서 제외한다.
5. 발표자는 동물군을 사전에 고르지 않는다. 첫 시연은 노루·동박새·호랑나비·붉은귀거북·참개구리와 빈 풍경 1장으로 한다. 심사자가 같은 종의 다른 사진을 골라도 동일한 추론 경로로 처리한다.

제주 CSV의 Amphibia 10행은 곧바로 독립적인 학습 클래스 10개가 되지 않는다. 북방산개구리와 큰산개구리의 과거 분류, 도롱뇽과 제주도롱뇽의 표본 기록을 검토한다. 국명 미대응인 `Hyla arborea` 1건은 보류한다. 청개구리는 제주 ID `JJ-001485`의 *Dryophytes japonicus*를 대표로 두고, 전국 도감의 *D. japonica* 항목과 국명 연결을 따로 검토한다. 동일 사진이 두 라벨에 들어가는 일을 막는다. [제주 양서류 현장조사(2004–2008)](https://library.nih.go.kr/ncmiklib/elib/kom/articleDtl.do?pk_pb_seq=PB06777236) · [제주 하천의 큰산개구리 등 4종 연구](https://www.riss.kr/search/detail/DetailView.do?control_no=d687a8e2c2f21ca7ffe0bdc3ef48d419&p_mat_type=be54d9b8bc7cdb09) · [국립생물자원관 청개구리 자료](https://species.nibr.go.kr/resoPath/reso_img_20250805_133416.pdf)

## 사진 확보와 선별

- 1차 범위는 성체 한 마리가 주피사체인 정지 사진이다. 올챙이·알·탈피각·여러 종이 섞인 사진은 별도 검증 전까지 미확인 대상으로 둔다. 화면 캡처에는 정답 종명, 워터마크의 종명, QR 등 정답 단서를 남기지 않는다.
- 목표는 종당 **독립 관찰 200건**이다. 학습 120건, 검증 30건, 잠금 평가 50건으로 제안한다. 원본 사진, 연사, 증강본, 인쇄·화면 재촬영본은 원본 관찰과 같은 묶음에 배정한다. 한 촬영자 또는 같은 촬영 세션이 여러 분할에 들어가지 않게 나눈다. 훈련에는 다양한 자세·조명·성별·배경과 제주 또는 국내 촬영본을 포함한다.
- 사진마다 출처 URL, 관찰 ID, 사진 ID, 촬영자, **사진 자체의** 이용조건, 동정 근거, 분할을 남긴다. iNaturalist의 전 세계 Research Grade 관찰 중 CC0 또는 CC BY 사진이 포함된 관찰 수는 후보 탐색에 사용한다. 건수는 학습 가능한 국내 사진 수와 다르다. 한 관찰에 포함된 각 사진의 라이선스를 다시 확인한다. [iNaturalist API](https://www.inaturalist.org/api) · [사진 라이선스 안내](https://help.inaturalist.org/en/support/solutions/articles/151000169918-someone-asked-me-to-share-a-hidden-location-or-collect-a-specimen-for-them-what-should-i-do-)
- 2026-11-12 위 조건으로 확인한 50종 중 **35종**은 전 세계 관찰이 200건 이상, **15종**은 200건 미만이었다. 예를 들어 노루 831건, 호랑나비 600건, 제주도롱뇽 63건, 줄장지뱀 40건이다. 실뱀은 9건이어서 1차 후보에서 제외하고 리버쿠터(1,415건)를 배치했다. 15종은 직접 촬영·제공 동의를 받은 자료·사진별 이용 허락이 있는 다른 공공 자료로 보완하며, 최종 평가 사진까지 확보할 수 없으면 지원 종 수를 줄인다. 종별 재조회 URL은 후보 목록에 수록했다. 황소개구리는 같은 종의 다른 학명으로 검색했다. [황소개구리 학명 대조](https://www.ncbi.nlm.nih.gov/Taxonomy/Browser/wwwtax.cgi?id=8400)
- 근연종(민물가마우지, 다른 장지뱀·개구리 등), 다른 동물군, 식물·장난감·빈 배경·흔들린 사진을 별도로 모은다. 수량이 적거나 사진만으로 일관되게 동정하기 어려운 종은 보류하고 후보표에 이유를 남긴다. 대상 밖 종을 임의의 지원 종에 배정하지 않는다.

## 모델과 카메라 연결

PyTorch의 사전학습 MobileNetV3-Large를 기본 비교 모델로 삼는다. 한 번의 추론으로 **활성 종 K개와 기타 1개**의 점수를 내고, 동물군은 선택한 종의 도감 메타데이터에서 읽는다. 동물군을 먼저 잘못 선택해 정답 종이 후보에서 사라지는 문제를 피한다. 기본 비교 모델에서 혼동이 많은 종은 데이터·촬영 범위를 조정한 뒤 성능을 다시 비교한다. [Torchvision 모델](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.mobilenet_v3_large.html)

공모전 단말에는 모델, 순서가 고정된 ID 배열, 전처리 사양, 검증에서 정한 문턱값, 버전과 체크섬을 함께 배포한다. 종 ID를 가나다순으로 다시 정렬하지 않는다. PyTorch → ONNX → ONNX Runtime Mobile 경로를 먼저 시험한다. 같은 이미지 20장에서 PC와 모바일의 상위 후보·미확인 결정이 일치하는지 비교한다. Android 우선으로 붙이고 iOS는 같은 입력·출력으로 확인한다. 원본 사진과 GPS는 기기에 두며 입력 텐서는 사진에서만 만든다. [ONNX Runtime 모바일 배포](https://onnxruntime.ai/docs/tutorials/mobile/)

입력은 사진 방향 보정 → 사용자가 선택한 대상 영역 또는 전체 사진 → 비율 유지 리사이즈·패딩 → RGB 224×224 → 학습과 동일한 정규화 순서다. 실제 학습 크기·정규화·채널 순서를 모델 명세로 고정한다. 모델을 로드해 재사용하고 추론은 UI 스레드 밖에서 실행한다. 늦게 도착한 결과는 현재 사진 ID가 요청 당시와 같을 때만 반영한다.

검증 세트에서 온도 보정과 종별 최소 점수 및 1·2위 점수 차를 조정한다. 기타 클래스가 우세하거나 이미지 품질이 낮으면 `unknown`, 1·2위가 비슷하면 `review`, 기준을 통과하면 `suggested`를 반환한다. 유사종을 보지 않고 정한 고정 90% 규칙은 쓰지 않는다. 약한 점수는 확정이나 자동 등록으로 연결하지 않는다.

**기기 내 결과 인터페이스 예시** (숫자는 형식 설명용)

```json
{
  "photo_id": "demo-018",
  "model_version": "demo-v1",
  "decision": "suggested",
  "candidates": [
    {"species_id": "JJ-004873", "taxon_class": "Aves", "score": 0.94}
  ]
}
```

제주 종은 Flutter 카탈로그의 jejuId, 전국 전용 종은 KTSN- 접두어를 뗀 문자열을 nationalId와 비교한다. 청개구리는 검토된 후보표 국명으로 보완한다. 도감명·학명은 이 매핑을 통해 조회한다. 사용자 확인 전에는 AI 제안 상태를 유지한다. 기록에 모델 버전·후보·판정·사용자가 고른 종을 별도 필드로 저장한다. 과거 촬영 기록에서 이 필드가 없으면 미판별로 표시한다. 재식별·정정으로 촬영 시각, GPS, 사진 파일이 바뀌지 않게 한다. 기존 저장소의 `identification=confirmed` 반영은 사용자 확인과 제주 위치 요건을 모두 만족한 일반 관찰에만 적용한다. 모델 누락·추론 실패·저장 공간 부족을 상태로 보여주고 재시도할 수 있게 한다.

## 시험과 통과 기준

아래 수치는 **출시·시연 목표**다. 학습 완료 후 실제 수치, 분모, 모델 버전 및 기기명을 기입한다.

| 시험 | 제안하는 통과 기준 |
|---|---|
| 잠금 평가 | 학습·튜닝에 쓰지 않은 종별 50개 관찰에서 원점수 Top-1을 종당 45/50 이상으로 목표. 종별 혼동표와 5개 군별 macro-F1도 함께 보고 |
| 확신하는 결과의 품질 | 확신한 결과의 정밀도 ≥95%, 지원 종 사진에서 확신 결과를 내는 비율 ≥80%. 분모를 함께 기록해 전부 미확인으로 보내는 경우를 구분 |
| 대상 밖 사진 | 미학습 근연종·빈 풍경 등 독립 사진 최소 200장 중 지원 종으로 확신하는 오판 ≤5% |
| 공모전 리허설 | 모델 고정 후 별도로 확보한 종당 3장의 정면·측면·다른 개체 사진을 실제 휴대폰으로 재촬영. 활성 50종이면 150장 모두 1순위·제안 판정, 부정 예시는 미확인을 목표. 실패한 종은 수정 후 새 잠금 세트로 재평가하거나 지원 목록에서 보류 |
| 휴대폰 | 비행기 모드에서 첫 모델 로딩 시간을 별도 기록. 로딩 후 촬영 미리보기에서 추론을 시작해 결과를 표시할 때까지 p95 2초 이내를 목표. 빠른 재촬영, GPS 거부, 앱 재시작, 기존 기록 재열람 확인 |

사진 3장 모두 맞았다는 사실은 그 종의 임의의 사진을 100% 맞힌다는 증거가 아니다. 무대에서는 **검증한 종 수·검증한 사진 수·미확인 수**를 말한다.

## 팀원별 첫 결과물

1. AI 담당은 5개 군에서 1종씩과 대상 밖 사진으로 수집→분할→학습→ONNX 내보내기→평가를 한 번 완주한다. 다음은 25종, 마지막은 기준을 통과한 최대 50종이다. 데이터·대형 가중치는 외부에 두고 저장소에는 출처·라벨·체크섬을 둔다.
2. Flutter 담당은 카메라 PR의 `lib/explore/camera.dart` 미리보기와 저장 기록에 동일한 식별 동작을 붙인다. 예시 응답으로 결과·미확인 화면을 확인한 뒤 실제 기기 모델로 교체한다. 심사에 쓰는 빌드에서 예시 응답을 끄고 모델 버전을 검증한다.
3. 백엔드·데이터 담당은 도감 ID와 분류군, 전국 전용 3종, 청개구리 이명 연결을 검토한다. 미판별→AI 제안→사용자 확인·정정의 저장 계약과 구버전 기록 호환을 검증한다. 사진·GPS 저장과 도감 통계가 중복 증가하는지 함께 확인한다.
